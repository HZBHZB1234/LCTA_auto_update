# 14 — 系统验证、完整交付与旧核心退役

> 执行计划，尚未实施。前置：01–13。本任务完成后，新系统成为生产入口；当前文档工作不执行切换。

## 任务目的

证明新系统确实实现作品级一致性，并以经过验证的新核心替代旧流程。验收对象包括译文、AI 协作、调度、持续修订和交付行为，不以“新架构能调用模型”作为完成标准。

允许一次性替换核心与配置体系；兼容工作只为必要资产与有效使用方式服务。

## 需要做什么

1. 整合从任务 01 累积的样例，建立按历史时点重放的真实更新集。每次重放只能读取当时已有的原文、权威和决定，避免偷看后来中文导致虚假的质量提升。
2. 比较旧系统与新系统的一致性、忠实性和中文质量，并分开记录时间、费用、延期比例与自动恢复情况。生产验收中人工必需操作次数必须为零，不用一个综合分掩盖条件错译等严重问题。
3. 验证关键设计的实际贡献：三语相比单语是否消除歧义，共同契约是否减少漂移，独立审查是否发现错误，动态调度是否减少基于过时决定的重做。
4. 验证不确定性处理：相关模型犯同一种错误、多角色共同受误导、权威自相矛盾、上下文缺失和近似检索误匹配时，系统能否补证或明确停止。
5. 对中断恢复、重复事件、乱序返回、版本交错和调度顺序变化进行系统验证；覆盖 LLC 分页漏项、历史改写、回滚、提交正文与发布资产不一致。追求质量约束与决定适用范围稳定，不要求随机生成文字逐字相同。
6. 建立交付环节：候选合并后完成游戏结构校验、权威适用性检查、一致性范围验收与完整包验证，再产生可追溯版本。
7. 给正式产物绑定完整输入身份：原文内容、LLC 提交与正式资产、知识与契约版本、自动裁决及可选外部纠错，以及影响结果的运行配置。单一 raw token 不再代表整个翻译状态。
8. 建设独立的新入口、运行配置和自动化流程，移除 translatekit 生产依赖、导入、继承、服务注册及旧翻译控制流。不是把旧框架包在新名字后面继续使用。
9. 迁入经过验证的游戏格式能力、权威材料、历史样例与必要资料；旧机器词表和译文只作为待核验材料，不因导入就获得权威资格。
10. 替换限制新架构的上游同步约定，明确哪些格式资料继续跟进上游、哪些核心由本项目独立维护。不能再通过整目录覆盖恢复被淘汰的旧模块。
11. 完成切换演练、回退演练和旧路径删除。发布记录、未决案件与长期资产仍应可读取，运行状态的转换要显式处理。

## 要新增的功能

- **历史时点重放工作台**：在受控资料范围内复现原文先到、权威后到的连续更新。
- **分维度质量报告**：报告应统一但未统一、应区分却合并、权威不一致、语义错误和语言质量，附可审查案例。
- **协作贡献评估**：比较启用/移除某角色或共同契约后的效果，撤掉没有价值的反复自评。
- **调度与恢复演练**：改变并发和执行次序、模拟失败，确认旧结果不能污染新决定。
- **无人值守连续回放**：没有人工输入时完成提交获取、术语整理、自动裁决、交付及后续补证恢复。
- **完整包交付**：将合格候选按游戏要求合并、校验、冻结为版本，保留可解释的输入与决定清单。
- **新旧资产分界**：可证明继承的能力与明确淘汰的路径各有记录，防止“暂时兼容”永久保留双核心。
- **受控切换与恢复**：能回到已验证且适配当前原文的交付版本，并保留新系统的知识修订记录。

## 质量验收标准

一致性和忠实性必须分别通过：不能把同一错误批量传播视为改善，也不能用更高平均分抵消人物、否定、数值、条件、机制或游戏结构上的严重退步。

在预先冻结的关键样例中，不允许新增已知的严重语义或结构错误；对新增发现及时扩充案例并修复。在覆盖不同文本类型的保留评测集上，展示有证据的一致性收益与中文质量，盲评和分歧复核不只依靠生成译文的同一模型。

上述人工标注和盲评属于开发阶段的质量评测，不是运行时发布前置。生产演示不得由人补词条、定译名、批准案件或修改队列来推动流程；自动延期比例和后续恢复成功率也应报告，避免靠全部拒绝翻译获得虚假的安全指标。

测试不能证明任意未来输入绝对零错。验收还要证明：可预见风险被识别并处理，无法裁决的关键问题不会被自动当作通过，优化项不会绕过必要核验。收益未被证实时不预先承诺提升百分比，也不以宏大架构代替对照结果。

## 交付与回退边界

一致性域是编辑和验收范围，最终仍需生成游戏能正常使用的完整包。不能为了宣称某域完成而漏掉必须字段，也不能让共享决定不同步的域拼在一起交付。

未解决的域只有在旧产物仍适配当前原文、结构和共同决定时才可保留旧版；否则应阻塞该版本，不能把旧译文强塞进新字段。已有且适配的权威内容可按已验证路径直接采用。

回退优先恢复经过验证的发布产物或仍兼容的运行版本。不能恢复旧词表热更新机制，让未审定机器译名再次变成长期标准；不能让旧程序读取并覆盖它不理解的新工作状态。

## 最终演示与完成标准

完整演示以下连续过程，而非分别展示几段无联系的示例：

1. 新版本出现跨文件角色、技能与剧情；AI 识别共同关系，研究三语并形成契约。
2. 调度器优先处理共性歧义，再并行相关内容；审校发现冲突，重开决定并共同修订。
3. 原意核验和中文编辑完成后，系统生成通过游戏格式检查的完整版本。
4. 原文未变，LLC 出现新 commit；系统自动读取实际差异、整理词条、核对发布资格，正式中文到达后修正词库、理解、上下文和受影响译文。
5. 遇到无法可靠判断的称呼问题，系统自动补证后延期；后续提交提供充分依据，系统自行唤醒并重新组织编辑。
6. 在修订过程中中断并恢复，旧任务晚返回也不能覆盖新决定；最终交付一致版本。

交付的生产入口直接使用 OpenAI 兼容 HTTP 请求，运行时不再依赖 translatekit；旧文件队列、巨型处理器、机器术语自动固化与受限上游同步路径退出生产。

整段演示不接受人工批准、手工清洗输入或手动重启任务。还需以原文不更新、LLC 仅更新 commit/发布资产的事件证明不会因 raw token 去重而跳过工作。

最终成果应包括可无人值守运行的新系统、质量对照材料、连续更新演示、自动发布与恢复说明，以及明确的旧核心退役清单。到此才算实现了新纲领，而非完成了若干新模块。
