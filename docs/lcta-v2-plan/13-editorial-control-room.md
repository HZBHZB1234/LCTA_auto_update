# 13 — 无人值守运行、自恢复与编辑观测台

> 执行计划，尚未实施。前置：03、05–06、10–12。下一步：[14 验证与切换](14-validation-and-cutover.md)。

## 任务目的

把此前各项自动能力连成能够长期独立工作的系统。维护者离线时，采集、研究、冲突处理、延期恢复、质量验收与发布仍能自行推进。

观测台用于解释和检查运行；关闭界面、无人查看报告或无人处理通知，均不能阻止正常生产。

## 需要做什么

1. 建立周期检查与事件唤醒入口，独立跟踪游戏原文、LLC commit、正式发布和待证任务。不要求上游主动推送，也不依赖维护者手动触发。
2. 将采集、持久任务、自动核验和发布准备接成连续运行流程；一次执行结束后仍能在下一轮自动接续。
3. 对服务限流、网络中断、进程退出和租约过期自动恢复。重复启动不得争抢同一提交或重复交付，永久配置错误与瞬时故障分别记录。
4. 建立争议自动处置策略：补充上下文、读提交历史、核对三语、独立反证、采用适用权威；仍无依据时进入有恢复条件的等待。
5. 自动管理预算与公平性。高影响问题得到必要研究，重复无效任务休眠，其他可处理范围继续；额度恢复后按规则续作，不能通过削减审校保吞吐。
6. 建立自动发布控制，只有完整包与一致性验收通过才进入提交；发布失败可恢复，中途新证据按版本规则处理，不能覆盖新产物。
7. 输出运行总览、四语证据、术语与角色卡、案件、影响范围、版本差异和质量报告，所有信息来自同一持久状态。
8. 提供可选纠错与诊断入口；外部意见按正常证据流程核验，不能成为解除正常流程阻塞所必需的操作。

## 无人值守的状态与处置

| 情况 | 自动行为 | 恢复或结束条件 |
|---|---|---|
| 新 LLC 提交出现 | 持久记录、获取完整变化、整理并核验知识 | 相关资料处理完成，进度安全推进 |
| 证据充分的名称或语义修正 | 更新知识与契约，修订并复核受影响内容 | 一致性域及完整包验收通过 |
| 三语或权威存在冲突 | 补证、独立读解、扩大相关场景，有限裁决 | 有可检查依据支持某决定 |
| 自动研究仍无结论 | 停止无效重复，延期受影响范围并登记缺口 | 新提交、权威或源文补齐实际证据 |
| 模型或 GitHub 暂时不可用 | 保留状态，退避重试，执行不依赖故障源的工作 | 服务恢复且输入仍有效 |
| 任务或进程意外退出 | 回收过期执行权，从已验收成果继续 | 任务恢复，旧返回不能重复提交 |
| 预算暂时不足 | 暂停未完成任务，保留质量标准 | 后续额度窗口或配置资源可用 |
| 当前完整包无法安全交付 | 保留仍兼容的已验收版本，否则延后新包 | 关键问题解决且整体通过验收 |

等待必须有具体原因和恢复条件，不能用“待处理”隐藏失败。定时复查先检查是否出现新证据或故障已解除，不无条件重复整套模型调用。

## 要新增的功能

- **自动运行监督器**：启动周期任务、检查活性、恢复中断，避免队列无人唤醒。
- **来源进度观测**：展示发现到哪个 commit、处理到哪里、哪些变更尚在核验以及与 Release 的对应状况。
- **待证唤醒索引**：按实体、字段、版本和来源匹配新证据，及时恢复相关任务。
- **自动故障恢复**：重试、退避、执行权回收、过时结果拒绝和发布重入去重。
- **四语证据工作台**：查看原文、权威中文、候选、对齐状态与相邻场景。
- **案件和影响视图**：解释冲突证据、自动决定、修订范围与延期原因。
- **资源与质量观测**：分开查看等待时间、用量、纠错价值、真实一致性与忠实性。
- **版本交付视图**：清楚显示已发布、正在修订、等待证据及无法适配当前原文的产物。

## 运行边界

无人值守建立在部署配置、有效凭据和可用资源之上；系统不能创造上游尚不存在的译文或自行恢复被撤销的权限。此类状态应自动保存、间隔探测并记录原因，不假装已经完成，也不转成翻译任务必须人工批准的流程。

人可以选择查看或提供纠错，但生产任务没有“待人工批准”状态。自动核验同样不可能证明绝对零错误；必须保留前述原意底线和未知问题的延期能力。

“为什么这样译”展示具体来源、可检验结论、版本和裁决理由，不要求模型私有思维链。观测台不是另一套状态机，也不能绕开验收强制发布。

## 交付与完成标准

关闭交互界面，不提供任何人工操作，连续运行跨越原文更新、LLC 提交、正式中文晚到、暂时故障与进程重启，最终自动交付合格结果。

另覆盖一次未知问题自动延期、后续提交补证后自动恢复的过程。系统应能解释为何等待及为何恢复，期间其他独立工作正常进行。

验收记录必须显示人工必需操作次数为零；依靠维护者修改状态、确认词条或点击继续才能完成的演示不算通过。
