# 12 — 权威迟到与持续重编辑

> 执行计划，尚未实施。前置：05、08–11。下一步：[13 无人值守运行](13-editorial-control-room.md)。

## 任务目的

让新系统持续维护作品的译文，而不是每次原文更新后运行一次便结束。LLC commit 到达、正式中文补齐、原文理解被纠正、术语条目撤回，都应能自动触发有范围的重新编辑。

“待权威”是正常工作状态；权威到达后的全局收敛是核心生产能力，不是后续维护脚本。

## 需要做什么

1. 为原文、LLC 提交、正式权威中文、自有词库与共同契约建立独立变化来源。原文未变时也能启动工作；同一发布标签的附件内容变化也能被识别。
2. 在接纳权威资料前确认来源、内容身份和对应原文版本，区分新补译、修订、撤回与疑似错版。不能因为下载时间更晚就认为适用于所有旧文。
3. 比较新权威带来的知识变化：除译名外，还包括人物身份、称呼、叙事视角、机制解释和表达习惯。相关原文理解可能需要一起重开。
4. 沿着实体、原文片段、知识、契约、上下文、草稿与历史交付的依赖查找影响，同时主动检索尚未进入词库的新称呼和遗漏引用。
5. 将影响组织成修订工作包：哪些内容可直接采用匹配的权威，哪些需要重译，哪些只需重新核验，哪些必须等版本或语义争议解决。
6. 重新组织必要的三语研究、术语整理、共同定约、相关稿件修订与全域审校；不得以“只改了一个名字”为由跳过可能受影响的指代、语法和机制解释。
7. 为进行中的任务处理版本竞争。旧契约下完成的稿件不能覆盖新决定；能保留的研究成果重新确认依赖后复用，需要重做的工作明确失效。
8. 将尚未收敛的项保留为可恢复任务，记录缺什么证据及什么事件能重启。进程退出、接口失败和计划维护不丢失已经核验的成果；运行恢复由系统触发。
9. 关联任务 05 的采集进度与待证项。新 commit 可能只补证而不产生权威变更，正式发布可能使旧提案取得来源资格；只唤醒实际受影响的问题，避免每轮无差别重试。

## 要新增的功能

- **多来源更新感知**：原文与权威中文各自更新，内容变化触发工作，不以单一 raw token 判定所有状态。
- **提交到修订的自动链路**：commit 的字段差异进入知识整理，知识版本变化进入影响分析，验收通过后自动交付。
- **权威差异研究**：区分名称替换与理解改变，产出有证据的变化说明。
- **影响传播与补漏发现**：既追踪已记录依赖，也重新搜索未被识别的提及，防止只修已入词库的句子。
- **修订工作包**：展示直接影响、间接影响、保留项、未决项与预期交付范围。
- **工作记忆失效处理**：被撤回的名称或解释同时从后续上下文、摘要、检索视图和可复用候选中退出。
- **待权威队列**：跟踪暂译实体及相关文本，权威出现后自动转入研究和修订，不把等待时间变成可信度。
- **范围完整的再交付**：同一决定覆盖的内容通过复核后共同进入新版本，防止同域一半改名、一半沿用旧名。
- **历史可解释性**：保留旧版本曾使用的证据与决定，清楚说明新版本为什么修订。
- **待证自动恢复**：以实体、版本及具体缺口匹配新增证据，无人操作也能从延期回到研究与修订。

## 必须明确的边界

权威迟到不意味着后来发布的中文必然与当前原文逐句对齐。遇到旧版中文、新版原文或同一来源自相矛盾，应先解决版本和适用范围，不能直接覆盖。

权威资料撤回后，已经依赖它的决定需要重新评估；不能静默恢复更早的机器译名并当作权威。新证据也不能倒写历史，让过去的版本看起来从未使用过旧决定。

机器暂译和共同编辑的结果仍是待审对象。被沿用多次、经过多个角色认可或已进入发布包，都不能使其自动升级为长期术语。下一轮使用前重新核对原文和可用权威，必要时重新研究。

## 交付与完成标准

演示一次完整连续更新：先对缺少权威的新内容完成联合编辑；原文不变而 LLC 新提交及正式中文到达后，系统自动整理资料、确认资格、找出跨文件称呼及间接上下文，重开决定、修订并完成一致交付，全程无需人工操作。

另需覆盖权威同标签换附件、权威撤回、原文版本不匹配和旧任务晚返回等情形。结果能区分已收敛、正在修订与尚缺证据，不能用“任务执行成功”掩盖未解决问题。

修订期间中断再恢复，应继续已有工作且不重复发布；未受影响的内容不需要被无理由重译。

另演示一个自动研究仍无法解决的案件：系统保存明确的恢复条件并延期，后续提交补齐证据后自动恢复并完成；不能以创建人审待办作为任务完成。
