# 08 — 建设一致性优先的动态调度器

> 执行计划，尚未实施。前置：03、06–07。下一步：[09 联合起草](09-domain-drafting.md)。

## 任务目的

替换按文件排队、优先文件先翻、其余文件并发的固定策略。调度器应按**共同知识依赖和翻译影响**安排工作，让必须统一的内容在共同决定后再并行执行。

本任务不让 AI 任意控制基础设施。AI 建议如何研究和分工，程序保证依赖、有效性、预算和提交顺序。

## 需要做什么

1. 根据作品关系图与总编计划形成一致性域：场景、角色的新剧情/语音、状态/技能一族、UI 概念等。
2. 找出域与域共享的关键决定，如人名、机制规则和人物关系；建立共同依赖节点。
3. 先运行高扇出、高错翻风险、资料缺口大的研究任务；决定稳定后解锁相关起草任务。
4. 相互独立的域并行，不强行等待全游戏其它内容。
5. 在执行中接收新发现的反例、权威修订和质量案件，动态暂停、重排和局部失效。
6. 为 AI 角色、模型、检索和复核分配预算。预算是资源边界，不是跳过关键核验的理由。
7. 定义任务完成与域完成：关键争议解决，相关稿件一起采用新的共同决定，经整域检查才能交付。

共同名称依赖必须区分已有权威与待权威新实体。有权威时共享范围明确的译名契约；没有权威时先共享原文身份与语义证据。若多个域需要共同确定暂译，把相关稿件纳入一次联合编辑和复核，再按需要拆分执行；不能借“公共依赖节点”之名把机器候选变成所有独立任务的强制词条。后续更新继续遵守重新核验规则。

## 要新增的功能

- **一致性域规划器**：跨文件成组，但避免简单共享高频人物名造成全游戏单大域。
- **关键路径识别**：显示“等待哪一项共同决定”“谁受影响”“决策更改需重做什么”。
- **风险感知优先队列**：机制、身份、否定、数字、权威冲突优先于无争议措辞润色。
- **动态子任务**：允许研究员或审查员提出补证，并仅暂停受影响范围。
- **并发约束**：同一共同决定下的译者读冻结契约，不以先完成的机器译文确定后完成者写法。
- **争议汇聚**：多个任务发现相同冲突时归并为一个案件，避免重复花费和多套结论。
- **资源控制**：按域和角色限流，预留新事件、权威迟到和关键修订资源。
- **局部重算**：决定改变后只重做真实依赖它的任务，同时防止漏掉没有显式引用却包含新术语的文本。

## 具体调度例子

一次原文更新同时出现新状态效果的名称/描述、三段技能说明以及两段角色对话。调度器先解决状态身份和名称依据；技能的三个字段在同一机制约定下起草；角色对话另形成场景任务，可以在机制研究期间并行。若审查员发现效果触发时序理解错，系统只失效受影响技能和关联解释，而不会无理由重翻全部对话。

若新中文权威在编译包前到达，同一域收到重编辑事件。该域要么完成新权威修订和验收，要么整体继续待发布，不能把名称的两种版本拼进同一包。

## 风险和退出条件

- 不把高影响判定押在“第一个 API 回复”；并发结果提交时检查依据版本。
- 调度器不得降低原意检查等级换取吞吐。预算耗尽可延迟域完成，不能把未审高风险字段算已完成。
- 给重复研究设置边界：没有新证据时关闭自动循环，等待相关提交、权威或源文变化；证据满足时自动恢复，不转人工必办队列。
- 记录为什么优先/暂停某域，以便发现错误的调度规则。
- 任务图节点过多时可合并同质工作，但合并不能使独立错误被遮蔽。

## 交付与完成标准

在跨三个文件类型的更新样本中，展示“共同研究→并行起草→发现反例→局部重排→整域验收”的完整运行。固定输入与回放响应后，改变并发度和响应到达顺序，不应改变决定的接纳资格或跳过应检查的任务；真实模型运行另评估质量稳定性，不承诺每次生成完全相同。

能够清楚说明一次更新何处耗时：资料不足、共享决策、模型拥堵、审查还是发布等待。速度优化先瞄准真正瓶颈。
