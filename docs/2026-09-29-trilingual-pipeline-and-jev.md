# KR／JP／EN 联合翻译、精确复用与 Jev 决策契约

> 2026-09-29，只读设计稿；所有数据结构和算法均为拟议接口。返回[总路线图](2026-09-29-future-capability-roadmap.md)，术语来源规则以 [Term Ledger v2](2026-09-29-term-ledger-v2-spec.md) 为准。

## 1. 三语能力的目标

当前请求已经携带三语，下一步不只是增加一段“参考日文和英文”的提示。每一阶段都要知道：三种文本是否真的对应、哪一种给出了什么证据、它们是否冲突、这些证据如何影响最终结果。

默认 KR 为原意和游戏结构的基准；JP、EN 是官方平行译本，用来补足主语、音译、语义、否定和机制条件。三者不是独立投票。JP/EN 互相一致也不能自动推翻 KR，KR 本身疑似缺陷则进入单独证据/例外规则。本计划不根据当前 `from_lang: EN` 推断实际主源；实施时明确 `semantic_primary=ko`，与遗留配置区分。

增益要通过分桶消融验证：KR-only、KR+JP、KR+EN、KR+JP+EN。不能预先声称三语一定更好；错位日英反而可能造成额外错误。

## 2. 统一翻译单元与身份

### 2.1 `TranslationUnit`

| 字段 | 语义 |
|---|---|
| `unit_id` | 逻辑身份，由文件域、实体稳定键、字段角色/嵌套选择器产生 |
| `unit_revision` | 本次原文值和结构上下文指纹；内容变化时更新，不让所有路径随之改名 |
| `source_snapshot_ids` | KR/JP/EN 每种语言的资产、文件版本；不能只存一枚 raw token |
| `logical_path` | 只按已知语言前缀规范化；保留目录、模式、章节域，不把变体文件合并 |
| `physical_pointers` | 每种语言当前 JSON Pointer；用于取值/写回，和跨版本逻辑身份不同 |
| `selectors` | `entry.id`、`level`、`coin.id` 等已验证的稳定键；允许字符串/整数类型不同且不混同 |
| `field_role/text_type` | name、description、dialogue、UI 等；由版本化解析器产生 |
| `texts` | ko/ja/en 的原始文本及 sha256；缺失为 null，不复制其他语言充数 |
| `structure` | 占位符、标签树、效果引用、可验证数字/单位结构 |
| `context` | 所属实体、说话人、受话人、章节、邻接 unit_id；缺失必须显式 unknown |
| `alignment` | 每语言对应状态、匹配依据及版本证明 |
| `authority_binding` | 可为空；对应权威字段及它适用的源版本证据 |

内容 hash 是版本标识，不替代逻辑 unit_id。数组下标只用来定位当前版本；不能把“下标 4”宣称为跨版本稳定身份。

### 2.2 对齐算法与失败路径

1. 验证三语包完整性和 source manifest，分别按文件类型解析。
2. 有稳定 ID 的 dataList 按 namespace/domain/id 连接；重复 ID 报错，不能用 dict 后项覆盖前项。
3. 嵌套数组先查已登记的稳定键，再验证局部语义结构。不存在稳定键时，名称、邻接锚点和顺序产生候选；只有能证实唯一对应时接受。
4. 无 ID 剧情以说话人/事件结构/前后锚点作单调序列对齐，支持一对多、多对一和插行，但自动翻译单元仍保留各自字段。不能把拼接后的对照句当成逐词对应证据。
5. 无法证实的 JP/EN 不进入该字段的强证据；可以在审阅页面显示“疑似相邻对照”，默认不送生成 prompt，避免污染。
6. 中文延迟到达时先找它对应的原文快照，或证明原文从已知对齐点至今没有变化。没有历史对应证据时标 `source_version_unknown`，仅靠日期相近/路径相同不补证。

对齐结果是 `verified/candidate/conflict/unresolved`；语言的内容状态是 `present/missing/stale`，二者分开。对齐正确但 JP 语义落后是 `verified + stale`，不能自动当最新的语义依据。

## 3. 三语证据如何参与每个环节

| 环节 | 三语的具体用途 | 输出与边界 |
|---|---|---|
| 实体发现 | 稳定 ID 的三语 name、已知 forms、重复专名 | source-only 实体和候选别名；没有中文就不造权威映射 |
| 短词消歧 | 用 JP/EN 的人物名、数量表达、机制词辨别 KR 同形词 | 对特定 occurrence 选择 sense，不能建立新中文定译 |
| 长词与嵌套 | 以多语别名与实体引用避免 `사` 覆盖 `사색` 一类内嵌误用 | spans 与排除原因；长词优先只是规则之一 |
| 主语和称呼 | JP 敬语、EN 显式主语/代词、KR 说话人信息互证 | 场景事实；缺证时不用默认性别或自造称呼 |
| 机制解释 | 对照次数、层数、上限、否定、触发先后与目标对象 | disagreement 清单；禁止“两个版本写 3 所以一定是 3” |
| 正文术语抽取 | 三语定位源实体，再在真实权威中文中抽取目标 span | 可以部分缺失；不要求逐词机械对齐或每语必须存在 |
| 生成 | 原文、有效对照、已确认术语、局部上下文分槽 | 一次联合生成，避免先翻三遍再盲投票增加成本 |
| 译后审阅 | 中文与三语机制/角色/目标对应情况 | 语义风险 Review；确定性结构错误单独阻断 |

### 3.1 分歧决策表

| 条件 | 默认动作 |
|---|---|
| 三语已对齐且语义一致 | 联合提供证据；按 authority 词条约束中文 |
| 一种对照缺失 | 使用已确认的其余语言；报告缺失，不惩罚为“判定失败” |
| KR 歧义，JP/EN 同时支持某已知 sense | 可请求判定器；若输出未达到标注集校准门槛则保持 unknown |
| JP/EN 互相矛盾 | 记录各自解释，以 KR 和明确结构事实为主；无足够依据不自动判定机制 |
| KR 更新、JP/EN 未同步 | stale 语言退出强约束；仅可作为被标记的历史背景，默认不进关键字段生成 |
| authority 中文名称与新机器建议不一致 | 在已确认相同实体和适用范围内采用 authority；机器建议只作候选记录 |
| authority 中文与新 KR 内容已不对应 | 中文不是当前字段的可复用译文；旧词条可能仍适用但必须重新判断 scope |
| 效果 ID 是同一实体，但描述说法三语不同 | 先保留 ID/结构事实；中文名称来自权威库；描述差异另作机制审阅 |

## 4. 权威翻译记忆与直接复用

### 4.1 三种层级，不把命中等同适用

**L0 当前字段权威复用**：同逻辑身份、原文版本对应已证实、authority 来源有效、源结构兼容。原文在历史链连续不变可继承；无法证明则不走 L0。

**L1 跨字段精确复用**：原始文本相同，且 `text_type/entity_sense/speaker_or_register/placeholder_signature` 等必要语境相容；若 authority 中存在多个有效中文而无法分清语境，返回冲突。名称必须绑定实体 ID 或已解决的 sense。

**L2 参考例句**：词面/BM25/实体召回的相似 authority 句对；只作为带来源的参考，不能直接写进输出。初期采用 SQLite 和普通索引；CJK 检索需明确分词或字符 n-gram 方案，不能假定默认 FTS 分词适合 KR/JP。

严格要求：L0/L1 必须来自真实 authority 或已经过同等证据资格校验的绑定；机器输出不进权威 TM。Jev 高相关性不能将 L2 升成 L1。

### 4.2 精确键与归一化

- 保存 `raw_text_hash` 与可检索的 `normalized_text_hash`，不要覆盖原值。
- 初期精确复用以原文本为准；允许的换行/NFC 兼容仅在明确规范化策略验证后开启，并同时验证结构签名。
- 不删全部空白、标点、数值、小数点、否定、富文本或引用 token 再称为“相同”。
- `>=` 与 `>`、2 与 3、`[EffectA]` 与 `[EffectB]` 都必须不命中。
- 可见中文相同不代表实例一致；同一句话不同说话人、不同称呼 scope 应允许不同中文。
- 查不到、冲突或低确定性要退出精确复用，不选择最高频/最新中文兜底。

### 4.3 authority 字段保护

权威复用字段标记 `immutable_for_generation=true`，不会收到可写输出 ID。修复模型只能返回本次允许编辑的机器字段；尝试修改权威字段视为无效编辑，保留 authority 原值并记录 finding。

权威名称与权威整句之间若出现不一致，保留已经确认属于当前版本的整句并开来源冲突报告；不可为了让术语统计变绿而直接改权威中文。若存在结构致命问题，则走包装兼容修复规则或隔离发布，记录未改正文的来源。

## 5. 逐次出现的术语决策

### 5.1 统一对象

```text
ResolvedOccurrence
  occurrence_id
  unit_id + unit_revision
  source_language + raw_source_hash
  raw_span[start,end) + quote
  candidate_bindings[(term_id, revision, form_id)]
  selected_binding | null
  decision = apply | exclude | unknown | conflict
  evidence_ids + decision_method + policy_version
  required_target_forms / forbidden_target_forms
```

原始 span 统一使用 Unicode code point 半开区间；前端 JS 的 UTF-16 下标须适配。NFC 等归一化匹配要保存到原始位置的映射；映射不唯一时不能强制 span。序号仅作显示，不代替绑定原文 hash 的稳定 ID。

同句两个 `이상` 分别是人物和数量关系时，必须有两个 occurrence。`exclude` 只排除此 occurrence 的候选 sense，不表示“整个句子里禁止李箱”或“以后文件都禁用该词”。

### 5.2 确定性解析优先

1. 结构化 `[EffectId]`、明确实体 name、明确 speaker ID 等可以直接定位 entity。
2. 执行 scope 和 forms 匹配，保留所有多义候选；按已审核的边界/长词规则排除误触发。
3. 需要语义判断的少量残余才请求 Jev 或生成式判定器。
4. 任何 unknown 都不被编译成强制译名；短词/高风险实体的 unknown 进复核，不能因“保守保留引用”而变相强制。
5. 下游 prompt、校验、修复共用同一 decision 对象。不能只从 glossary 删除，让实际含义与否定范围丢失。

## 6. Jev 服务化与校准

### 6.1 与已有实现的差别

现有实现是块级二选一并只删除高置信不适用引用。新接口保留 `off/shadow/enforce` 三模式：

- `off`：确定性规则＋兼容的 LLM 判定器。
- `shadow`：Jev 只记结果和指标，生成仍走固定基线。
- `enforce`：仅对已通过标注集验证的任务/类别启用；未知位置继续回退。

统一返回为 `apply/exclude/unknown/conflict`，无论底层 Jev 或 LLM，适用范围、缓存和校验契约相同。回退不得回到旧版整词删除语义。

### 6.2 三类任务

| 任务 | Jev 题型 | 建议答案集合 | 不能做什么 |
|---|---|---|---|
| occurrence 消歧 | Choice | 候选 sense A/B、普通词、其他、信息不足 | 不自由写中文、不以二选一逼出适用 |
| 抽取验证 | Choice/Noul 分题 | 源片段完整、目标片段同指、证据冲突等独立判断 | 不取代程序 span 检验；不把概率相乘当权威资格 |
| authority 例句排序 | Score 或 Choice | 根据实体/机制/角色相似程度的等级，含不适用 | 不从机器历史抽 few-shot、不决定直接复用 |

每题只解决一个有限判断；外部文本和 term notes 当数据，而非可覆盖系统契约的指令。state 包含准确 span、三语文本、已知结构事实、候选 authority 依据、缺失/分歧状态，不能只给整块文本让模型猜“此处”。

### 6.3 请求、答案和回退

- 按 state token、每题长度和问题数分批；实际服务限制于实施前核实。不能让整个更新所有字段塞入单请求。
- 同一请求中的问题独立评估，实体合并等依赖问题不能假装同步互相可见；需要下一阶段显式使用前一阶段确认结果。
- 答案必须覆盖预期 qid；缺项逐项 unknown，未知选项/NaN/越界概率/错误 schema 逐项拒绝。
- 低 confidence 不是 applicable；记录 abstain，再依风险回退或待审。
- `429/5xx/timeout` 有界退避、抖动、尊重 Retry-After、共享调用预算和熔断；错误响应不缓存为否定结论。
- 单项回退仍使用相同 occurrence ID 和上下文；不能使部分成功项被整请求重试反复收费。
- 固定模型版本；缓存键包含 endpoint provider、模型、schema、问题模板、三语内容、候选 binding revisions、scope/authority snapshot 与归一化版本。
- 保存供应商原始 probabilities/usage；Noul 不伪造独立 confidence；Score 不与概率混用。

### 6.4 上线前指标

逐类别报告误套率（错误 apply）、误排率（错误 exclude）、abstain/回退率、自动覆盖率、分歧召回、p50/p95 延迟和总费用。分 KR 短词、长实体、三语缺失/分歧、角色、机制字段统计。

阈值不先写死成 0.9=90% 正确。开发集拟合每类阈值，留出集测选择性风险与覆盖率。对 precision 接近 99% 的目标需要足够样本与置信区间；十几条全对不足以上线。样本不足的类别继续 shadow。

离线规则对比先固定判定结果；测试 Jev 本身时允许改变判定结果但固定生成输入和其余配置，并报告不同回退率，不剔除失败让指标虚高。

## 7. 生成、场景与角色

### 7.1 稳定输入包

提示按固定槽位构建：任务和可编辑 ID → KR 原文 → 对齐日英及分歧 → occurrence 约束 → 已确认角色/称呼事实 → 少量 authority 例句 → 输出契约。

一个场景/实体组可以在同一生成任务中联合翻译，利用同组原文维持一致性。不能以“第一块先译出来”为理由把该机译专名送给后续块当已定译名。权威未到的新实体可能仍存在暂时异译，这是明确可见的质量边界；在约束不允许机器词表复用的前提下，不能承诺零异译。

角色事实覆盖 StoryData、PersonalityVoiceDlg、BattleAnnouncerDlg，及有可证实角色归属的其他文本。只注入场景所需角色、说话人、受话人，且限制条数/长度。词库里未提到的性别、敬语与关系保持未知；不靠文件名猜人后永久入库。

场景摘要来自三语原文和可核验事实；实体以稳定 ID 标记。中文摘要若含未确认机译名会形成间接回流，默认禁止作为未来任务上下文。authority few-shot 只包含当时已知、范围相容的例句。

### 7.2 预算初值（可配置，待实测）

- 优先保存所有必须的结构和 authority 约束；预算不够先拆任务，不截掉必须字段。
- 每字段相似例句初值最多 3 条；场景角色初值最多 8 个，超过按场景切分。
- 问题/生成/修复共用 run 预算，内容修复每 unit 初值最多 2 轮。
- 降级先移除弱相关例句、远邻原文；保留当前三语证据质量信息。预算耗尽记录 deferred/fallback，不假装完成。

这些是可操作的初值，不是已验证的最佳参数；真实端点费用、模型上下文限制在 W0/W5 校准。

## 8. 验收与局部修复

### 8.1 检查结果分级

| 结果 | 示例 | 动作 |
|---|---|---|
| `InvariantViolation` | JSON 无法写回、字段丢失、引用 token 错、越权编辑 authority | 阻断该结果；先局部修复，耗尽后按发布策略回退/阻断 |
| `TerminologyViolation` | 已证实适用的权威 binding 明确未落位，目标区间能确定 | 对该机器字段局部修复；适用性不确定则降为 Review |
| `ReviewFinding` | 同源异译、多义不明、语气/机制疑似差别、权威内部不一致 | 报告和待审，不能被悄然当硬错误无限重试 |
| `OperationalFailure` | 超时、限流、预算耗尽、资产不可得 | 恢复/延期，与翻译质量分开 |
| `Unverified` | 词库空、没有适用证据、语言错位 | 显式报告覆盖不足，不能作为 clean |

术语落位使用 `not_applicable/applied/partial/missing/unverifiable`。目标词在整字段出现一次不能证明两个源 occurrence 都满足；无法确定多次出现的对应关系时标 unverifiable，不能为凑次数强行重复中文。

中文 `forbidden_forms` 同样只在已绑定 occurrence/scope 生效。目标与源相等不一定漏译（ID、数值、专用 Latin 名称），需要受保护字段规则。

### 8.2 修复协议

修复请求携带 unit/occurrence、原文、机器 draft、具体 finding、所需权威形式。模型返回定位编辑 `{unit_id,before_hash,range_or_pointer,expected_before,replacement}`；程序核对允许编辑列表、旧值、结构和绑定版本，再应用到临时副本。

修复后重新跑结构、数字/引用和术语检查；回归则保留原 draft 并产生 finding。禁止全局 `str.replace` 改词；禁止只因为模型返回“已修正”就当成功。transport failure 仅重试传输，不因此改 prompt。

## 9. 重点场景验收清单

- `사색` 内的 `사` 与独立的地支 `사` 共存：内部误匹配排除，后者不受连坐。
- 同句 `이상` 人名与数量关系并存：两个 occurrence、不同 sense。
- `피주머니` 在间章与 BUFF 两种范围：按权威 scope 区分，不能投票合一。
- 新 KR 描述数值已改，旧 JP/EN 仍为旧值：不能多数覆盖 KR。
- 同 ID 嵌套等级插入、剧情插行：日英不能按旧数组下标错配。
- 同 raw token 下 authority 迟到、中文修订或资产重传：会生成新的输入身份和影响任务。
- 先机译角色/效果名再翻技能：机译名称不得通过角色/affects 字典回流。
- 同场景人名缺席但代词出现：仅采用已证实身份事实，不默认性别。
- 相似技能描述只差 `[EffectId]`、层数或否定：不走精确 TM。
- authority 到达后，旧机器译名同时出现在普通字段、缓存和摘要：所有通道均被发现并失效。
